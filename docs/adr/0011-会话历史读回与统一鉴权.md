# ADR-0011：会话历史读回与统一鉴权

- 状态：已接受
- 日期：2026-10-23

## 背景

消息早已落库（ADR-0007 的 sessions/messages 表，Agent 循环经 persist 回调全程写入），但历史"只进不出"：

1. 无读回接口，历史无法查证——前端刷新即丢，看起来像"没保存"。
2. `POST /chat` 不鉴权：知道 session_id 即可向他人会话写入。
3. sessions 行创建后不再更新，无"最近活跃"语义，做不了会话列表。
4. 审计排查（tool 调用、越权防护验证）只能直接查库。

需求范围：刷新恢复会话、会话列表回看、审计留痕。**不含**跨会话长期记忆。

## 决策

- **统一 token 校验**：生产模式下 `/chat` 与全部新读回接口都要求携带签名 token（ADR-0004 体系），且 `token.user_id` 必须等于会话归属者（所有权校验）；demo 模式豁免。校验集中在路由层，复用 `IdentityProvider`。
- **两个读回接口，不混一个契约**：
  - `GET /sessions/{id}/messages`：面向终端用户，只返回 user/assistant 消息，tool 消息不透出。
  - `GET /sessions/{id}/events`：审计排查用，全量返回含 tool 消息；v1 与用户接口同一套所有权校验，不做 admin 体系。
- **游标分页**：messages/events 均支持 `?limit=`（默认 50）与 `before=<message_id>` 游标，取游标之前一页、按时间正序返回。
- **`last_message_at` 专用字段**：sessions 表新增该列，`append_message` 时同步写入；会话列表按其倒序。不动 `updated_at`（它是公共字段，语义是"行本身变更"，不承载活跃度）。
- **前端本期做满**：localStorage 持久化 session_id，启动时拉取消息回显（404 则静默开新会话）；会话列表侧边栏一并实现。

## 备选方案

- **单接口 + `?include=tools` 开关**：否。审计语义与用户展示语义混在同一契约，未来加耗时/usage 字段时会互相拖累。
- **会话级凭证**：否。更细粒度但引入新凭证体系，复杂度不成比例；签名 token 体系已存在且够用。
- **offset 分页**：否。并发追加时页会漂移。
- **append 时 bump 会话 `updated_at`**：否。让公共字段承载业务语义，排查时反而困惑。

## 影响

- 正面：历史"可见、可续、可查"；写入口子（/chat）与读回口子一并纳入同一鉴权模型；会话列表有了正确排序依据。
- 负面：存量调用方（若有）需给 `/chat` 补 token；messages 表数据量随 tool 消息增长，events 接口依赖游标分页兜底；`last_message_at` 需要一次 Alembic 迁移并回填存量数据。
- 后续：审计字段（耗时、usage 落库）与 admin 权限留给审计需求真正出现时再议。
