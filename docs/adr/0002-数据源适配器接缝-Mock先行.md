# ADR-0002：数据源接缝——按领域的适配器协议 + Mock 适配器先行

- 状态：已接受
- 日期：2026-10-22

## 背景

订单来源尚未确定，且未来可能不止订单一个领域。项目最核心的模块边界就是**数据从哪里来**这条接缝。

## 决策

- 项目只定义**按领域的适配器协议**：订单领域定义 `OrderAdapter`，售后领域定义 `AftersaleAdapter`，协议归各领域插件所有（见 ADR-0003）。
- 内置 `MockShopAdapter`：实现全部内置领域协议，附带 demo 种子数据（模拟商城：订单、售后单），保证 clone 后即可跑通全链路。
- 适配器是工具访问外部数据的**唯一通道**：领域工具的实现只调用适配器方法，不直连任何平台 API 或数据库。
- 社区接入新平台（淘宝开放平台、Shopify、自建商城）= 实现对应领域的适配器协议并注册，核心零改动。

## 备选方案

- **先对接一个真实平台**：被否。真实平台审批/沙箱周期长且强绑定，阻塞框架核心迭代；先 Mock 穿通接缝，真实平台成本后置到适配器内部。
- **统一数据推送约定（商家推数据进来）**：被否。把"数据同步"问题引入第一版，且与"查询"语义不匹配。

## 影响

- 正面：接缝真实（有 Mock 与未来真实平台两个适配者）；贡献路径清晰；demo 开箱即用。
- 负面：Mock 与真实平台行为差异（分页、限流、脏数据）由适配器实现者消化，需要一份适配器实现指南约束契约（分页、错误语义、鉴权）。
