# ADR-0001：项目定位为开发者框架，内置物皆为示例集成

- 状态：已接受
- 日期：2026-10-22

## 背景

ShopPilot 是开源电商客服 Agent 项目（FastAPI + DeepSeek + Function Calling）。当前没有真实订单来源，未来可能扩展到订单以外的领域。需要回答：这个项目给谁用、核心资产是什么。

## 决策

ShopPilot 定位为**开发者的框架/脚手架**：别人基于它构建自己的电商客服产品。由此推论：

- 核心资产是**扩展接缝与文档**，不是某个具体功能；
- 一切内置物——React 聊天窗、Mock 数据源适配器、demo 种子数据——都定位为**示例集成（sample integration）**，证明接缝可用，而非产品本体；
- README 与文档以「快速上手 + 如何接入你自己的订单系统 + 如何新增领域」为中心；
- 扩展点接口的稳定性优先于功能数量。

## 备选方案

- **中小商家自部署**：被否。会迫使项目向"开箱即用产品"演进，挤压架构通用性。
- **自运营 SaaS**：被否。多租户、计量、隔离等重运营能力与框架定位冲突，且远超第一版范围。

## 影响

- 正面：架构决策有了统一的裁判标准——"这让接入方更容易还是更难？"
- 负面：对非开发者用户的开箱体验要求降低，需要文档明确期望。
