# ADR-0004：用户身份——服务端签发 Token + IdentityProvider 接缝

- 状态：已接受
- 日期：2026-10-22

## 背景

查订单必须知道"我是谁"，否则任何会话都能越权查询。这是框架第二个核心接缝。

## 决策

- **身份由接入方服务端签发**：商家后端用共享密钥对包含 `user_id`、`exp` 的 payload 做 HMAC 签名，前端（聊天窗/渠道方）凭签名 token 向 ShopPilot 创建会话。
- 框架定义 `IdentityProvider` 接口负责 token 校验与身份解析，内置两个实现：
  - `HmacIdentityProvider`：生产形态；
  - `MockIdentityProvider`：demo 模式下免签发，直接映射到 Mock 商城的种子用户。
- 解析出的 `Identity` 挂在**工具执行上下文**上随调用传递；**用户身份永远不出现在 LLM 可见参数里**，工具参数不含 user_id，杜绝模型编造/被诱导传入他人 ID。
- **越权防护契约在适配器**：适配器实现必须按传入的 `Identity` 做数据过滤，这是适配器实现指南中的强制条款。

## 备选方案

- **前端直接传用户 ID**：被否。demo 最简但会被误当成安全方案，框架定位下这种误用代价高。
- **对话内验证（手机号/验证码）**：被否。体验差，且把渠道相关的验证逻辑绑进了对话流。

## 影响

- 正面：身份这条接缝清晰；生产接入路径真实（商家后端签发是普遍模式）。
- 负面：生产模式下接入方需要写一点签发代码（提供签名示例代码缓解）；token 失效/续期策略第一版从简（exp + 重新开会话）。
