# ADR-0003：领域扩展模型——ToolSet 插件注册，单 Agent 多工具

- 状态：已接受
- 日期：2026-10-22

## 背景

后续不止做订单（物流、商品、营销……），需要决定新领域以什么方式插入架构。

## 决策

- **一个领域 = 一个 ToolSet 插件**，包含三件东西：
  1. 工具声明（OpenAI function calling schema + 实现）；
  2. 该领域要求的适配器协议（如 `OrderAdapter`）；
  3. 领域系统提示片段（注入 Agent 的角色知识）。
- ToolSet 向 Agent **注册**即生效，框架核心只认识 ToolSet 抽象，不认识任何具体领域。
- **单 Agent + 多工具**：所有领域的工具挂在同一个 Agent 的 function calling 循环上，工具名命名空间化（`orders__query_order`、`aftersales__list_aftersales`）避免跨插件冲突。
- 内置两个 ToolSet：`orders`（查订单/订单明细）、`aftersales`（查售后单）。

## 备选方案

- **多 Agent + 路由**：被否。隔离性好但引入路由准确性、跨 Agent 上下文共享、多倍 LLM 调用成本，第一版收益不抵复杂度。
- **单体分包、出现第二个领域再抽象**：被否。与框架定位（ADR-0001）矛盾——接缝本身就是这个项目的卖点，等不起"两次规则"。

## 影响

- 正面：新领域零核心改动；工具按插件启停，天然支持"按商家裁剪能力"。
- 负面：工具总数增长会膨胀上下文、干扰工具选择——将来需要工具筛选/分组策略，届时单 Agent 内解决（按会话身份/意图裁剪注册的工具），暂不预付。
